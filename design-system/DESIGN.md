# BikesNest Design System

> Category: Community product design system
> Surface: Responsive web (desktop-first, mobile-aware)
> Direction: **Human-approachable** — calm utility with a trustworthy green-teal accent

Derived in full from the source project "Check Ui Design Md File There" (BikesNest, a community-maintained bike-parking finder). Every token below is extracted verbatim from the shipped prototype screens (`p1-landing.html` … `e2-error.html`, generated by `scripts/gen_d.py`, `gen_m.py`, `gen_m56.py`), not invented.

## Product context

BikesNest is a responsive web application where cyclists find, add, and maintain a shared map of bike parking spots. The source project ships 33 complete screens across six surface groups:

- **Public discovery** (`p1`–`p7`): landing page, search results with freshness filters, parking spot detail with photo gallery and review history, plus privacy/terms/cookies/about pages.
- **Authentication** (`a1`–`a5`): registration, login, email verification, password reset.
- **Account** (`c1`–`c7`): profile, password/email settings, favorites, contribution history, privacy controls, data export.
- **Contribution** (`d1`–`d3`): add a parking spot, propose a change to an existing listing, write a review.
- **Moderation** (`m1`–`m6`): moderation overview, photo queue, reports queue, proposal review, user administration, audit log.
- **Errors** (`e1`–`e2`): not-found and server-error pages.

Core capabilities the design must support: crowdsourced listing with photo evidence, freshness/status tracking per record, moderator review workflows with approve/reject decisions and reason capture, and transparent community accountability (audit log, contribution history).

**One sentence:** A warm, plain-spoken civic utility that earns trust through soft neutral surfaces, one green-teal accent, honest data photography, and restrained rounded components — never through gradients or decoration.

---

## 1. Visual Theme & Atmosphere

BikesNest is a crowdsourced directory of bike parking spots, kept honest by community contributions and moderator review. The interface should feel like a well-kept neighborhood tool: legible, friendly, and quietly competent.

- Near-white cool gray backgrounds; pure-white cards; hairline borders instead of heavy shadows.
- One accent family (green-teal, OKLch hue 170) carries brand, links, active states, and primary actions.
- A semantic "freshness" scale (fresh green → aging amber → stale orange) plus red for danger encodes data health across search results, moderation queues, and reports.
- Real street photography (Pexels, credited) is the only imagery. No illustration, no hand-drawn people, no gradients as decoration.

## 2. Color

All values are OKLch. Raw values live only in the token block (`colors_and_type.css` / the Tailwind config); screens reference token names.

| Token | Value | Role |
| --- | --- | --- |
| `bg` | `oklch(98% 0.004 240)` | Page background (cool near-white) |
| `surface` | `oklch(100% 0 0)` | Cards, panels, sheets |
| `fg` | `oklch(20% 0.02 240)` | Primary text (near-black, cool) |
| `muted` | `oklch(45% 0.018 240)` | Secondary text, inactive nav, meta (≈7:1 on `bg`, up from 50% L's ≈5.6:1 — WP21 a11y pass) |
| `line` | `oklch(90% 0.006 240)` | Hairline borders, dividers |
| `accent` | `oklch(56% 0.12 170)` | Brand green-teal: links, active states, primary buttons |
| `accent-strong` | `oklch(45% 0.11 170)` | Accent text on tinted backgrounds (≥4.5:1) |
| `accent-dark` | `oklch(40% 0.10 170)` | Primary button hover |
| `accent-soft` | `oklch(56% 0.12 170 / 0.12)` | Accent tints, badges, active nav fills |
| `scrim` | `oklch(18% 0.015 240)` | Overlays, lightbox, dark photo badges |
| `fresh` | `oklch(58% 0.13 155)` | Data healthy / approved / verified |
| `aging` | `oklch(68% 0.12 75)` | Needs re-check / open report |
| `stale` | `oklch(55% 0.16 35)` | Unverified / aging data |
| `danger` | `oklch(47% 0.17 30)` | Destructive actions, rejections |
| `danger-soft` | `oklch(47% 0.17 30 / 0.08)` | Danger tint surfaces |

Rules:

- **One accent.** Green-teal appears at most twice per screen as a solid fill (primary CTA + one highlight); everything else uses `accent-soft` tints.
- **Semantic colors are data, not decoration.** Fresh/aging/stale/danger always describe record status; never use them for section styling.
- Hover = background shift of +0.05–0.10 L on the neutral scale (`oklch(20% 0.02 240 / 0.04–0.06)` washes) or `accent-dark` on solid accent. Text color never lightens on hover.
- Dark-on-photo text uses `scrim` at 0.78–0.92 opacity with white text.

## 3. Typography

| Role | Stack | Usage |
| --- | --- | --- |
| Display | `"Avenir Next"`, `-apple-system`, `BlinkMacSystemFont`, `system-ui`, sans-serif | h1–h3, page titles, card titles. Bold (700), `tracking-tight`, balanced wrapping |
| Body | `-apple-system`, `BlinkMacSystemFont`, `"SF Pro Text"`, `system-ui`, sans-serif | Paragraphs, labels, nav, table text |
| Mono | `ui-monospace`, `"SF Mono"`, `Menlo`, monospace | Counts, coordinates, IDs, timestamps, statuses |

Scale (from the source screens):

- Hero display: 48–60px / 1.08, bold, white-on-photo (landing only)
- Page title: 30–36px bold · Section title: 20–24px bold · Card title: 18px bold
- Body: 15–16px / 1.6 · Meta & captions: 13–14px · Badges/counts: 11–12px
- No display serif is used anywhere; Avenir Next is the only display face. (No webfont files ship — Avenir Next is assumed present on macOS devices and falls back to the system stack.)

## 4. Spacing

- Base unit 4px; work in 4/8/12/16/20/24/32/40/64.
- Card padding: 20–24px. Page gutter: 24px (mobile) → 32px (desktop). Shell max-width **72rem** (1152px), centered.
- Form rows: label above field, 6px gap; 20px between fields; helper text 13px under the field.
- List/table rows: 12–16px vertical padding, `line` dividers.
- Radius: `rounded-md` 6px (inputs, small buttons) · `rounded-lg` 8px (buttons, nav items, inner blocks) · `rounded-xl` 12px (cards, media tiles) · `rounded-2xl` 16px (hero panels, modals) · `rounded-full` (badges, chips, avatars).

## 5. Layout & Composition

- **Public pages** (landing, search, details, legal): top nav with wordmark → full-bleed photo hero or sticky search header → content column ≤ 72rem → multi-column footer.
- **Authenticated shell**: sticky header (wordmark, search, avatar menu) → optional sub-nav tabs → main grid (2-col: 2fr/1fr on desktop, stacked on mobile) → slim footer.
- **Moderator shell**: same skeleton with a moderation tab bar (Moderation overview · Photo queue · Reports queue · Proposal review) and a "Signed in as Moderator" badge.
- Detail pages lead with a photo gallery; data (status, capacity, coverage, freshness) sits in a white card beside it. Maps/geodata appear as bordered cards, never as background.
- Density is medium: generous whitespace in marketing areas, tighter 12–16px rhythm in queues and tables. Mobile never scrolls horizontally; grids collapse to single column and the nav collapses into a menu.

## 6. Components

Component shapes observed across the source screens (implemented in `ui_kits/app/`):

- **Buttons** — Primary: `accent-strong` fill, white text (`accent` itself is ≈4.4:1 with white — under the 4.5:1 text minimum; `accent-strong` is ≈7:1 — WP21 a11y pass), `rounded-lg`, h-10, semibold, hover `accent-dark`. Secondary: white/`surface` fill, `line` border, `fg` text, hover neutral wash. Danger: `danger` fill, white text, hover darker (`oklch(40% 0.15 30)`). Ghost/text links for tertiary actions. One primary button per action per viewport.
- **Inputs** — h-10/11, `rounded-md`, `line` border, white fill, focus-visible 2px `accent-strong` outline with 2px offset. Labels 14px medium; hints 13px muted; errors 13px `danger` with a `danger`-bordered input state.
- **Cards** — `surface` fill, `line` border, `rounded-xl`, `box-shadow-card` (`0 1px 2px …0.06, 0 8px 24px …0.08`). Optional icon tile: 44px `rounded-xl` `accent-soft` fill with `accent-strong` icon.
- **Badges/chips** — `rounded-full`, 11–12px semibold, tinted fill (`accent-soft`, `fresh/10%`, `aging/12%`, `danger-soft`) with matching strong text; outlined variants use 45%-alpha borders.
- **Tables/queues** — `surface` rows with `line` dividers, mono counts, status chips, row-level actions (h-9 secondary buttons) right-aligned.
- **Header/nav** — sticky, `bg` at 0.9 opacity + backdrop blur, `line` bottom border; active item `font-medium text-fg`, inactive `text-muted` with neutral hover wash.
- **Modals/lightbox** — `scrim` at 0.78–0.92 overlay, `surface` `rounded-2xl` `box-shadow-pop` panel, `rounded-full` close button.
- **Product-specific** — parking spot card (photo, name, status chip, distance, capacity), freshness meter, contribution form with review-step summary, moderation decision card (approve/reject with reason radios).

## 7. Motion & Interaction

- Transitions: `transition-colors` (~150ms) on hover states; no transform-based entrances, no parallax.
- Focus: global `:focus-visible` outline 2px `oklch(45% 0.11 170)`, offset 2px, 4px radius — never removed.
- Overlays open instantly with the scrim fade; the lightbox closes on scrim click and Escape.
- Queues update counts in place; destructive actions (reject, hide, restore) swap the row action and reflect state immediately.
- `prefers-reduced-motion` honored: no animation beyond opacity.
- Text is never made lighter/grayer on hover; contrast never decreases in any state.

## 8. Voice & Brand

- Product name: **BikesNest** (camel case, one word). Tagline register: plain, civic, encouraging — "Find a safe spot for your bike", "Help keep the map fresh".
- Sentence case everywhere, including buttons and headings. Terminology is concrete: "parking spots", "contributions", "photo queue", "reports" — never "assets", "entities", "submissions pipeline".
- Moderator copy is neutral and procedural: state what happened and what to do next ("This photo was rejected — not of this location").
- Numbers are data, not marketing: exact counts, distances in km, capacities as integers. No invented superlatives.

## 9. Anti-patterns

- No gradients on any background layer; no purple/blue washes; no glassmorphism beyond the single sticky-header blur.
- No emoji as functional icons — icons are inline Lucide, stroke-based, 16/20px.
- No second solid primary button competing with the page's main action.
- No inventing tokens outside this palette; no raw hex values in screen code.
- No hover state that lightens text or drops contrast; no disabled-only affordances for hover feedback.
- No placeholder/lorem copy, invented metrics, or fictional brands — sample content uses real, credited Pexels photography and plausible civic data.
- No horizontal scrolling on mobile, no clipped table cells, no `nowrap`-forced headings.
- No illustrations, hand-drawn scenes, or 3D renders as imagery.
